## 3. SAM 的核心机制

### 3.1 `SystemAddressMapRN`

`SystemAddressMapRN` 负责将一个 `RN` 发出的请求映射到某个目标 `HN`。在当前实现中：

| 特性 | 说明 |
|---|---|
| 目标集合来源 | `TopoSys` 在构建时把所有 `HN node_id` 按顺序加入 `SAM` |
| 单目标情况 | 只有一个 `HN` 时，永远返回该 `HN` |
| 多目标情况 | 使用基于物理地址的 XOR 哈希 |
| 目标数量要求 | 当前实现默认最适合 `2^n` 个目标；非 2 的幂虽然不报错，但可能有目标长期不被选中 |

在 `2` 个 `HN` 时，规则可简化为：

```text
select[0] = XOR(PA[6], PA[7], ..., PA[51])
```

于是：

| `select[0]` | 结果 |
|---|---|
| `0` | 选择目标表中的第 0 个 `HN` |
| `1` | 选择目标表中的第 1 个 `HN` |

对本次运行来说：

| 目标表顺序 | 实际目标 |
|---|---|
| index `0` | `HNs0 = Mesh6.local0` |
| index `1` | `HNs1 = Mesh8.local0` |

因此本次运行里可以直接记为：

| XOR 结果 | 最终去向 |
|---|---|
| `0` | `Mesh6` |
| `1` | `Mesh8` |

### 3.2 `SystemAddressMapHN`

`SystemAddressMapHN` 负责将一个 `HN` 发出的请求进一步映射到某个目标 `DRAM`。它和 `SystemAddressMapRN` 使用同一套 XOR 结构：

| 项目 | 说明 |
|---|---|
| 单 DRAM | 固定走唯一一个 DRAM |
| 多 DRAM | 同样使用 `PA[6:51]` 的 XOR 哈希 |

不过本次运行只有一个 DRAM：

| DRAM 数量 | 结果 |
|---|---|
| `1` | 所有 HN 最终都走 `Mesh6.local1` |

因此本次分析的关键在 `RN -> HN` 这一跳，而不在 `HN -> DRAM`。

## 4. TopoSys 中 SAM 是如何挂上的

在 `L2L3DramSys5x3` 中：

| 流量源 | 对应 SAM | 目标集合 |
|---|---|---|
| 主 L2 / 主 RN (`Mesh0.local0`) | `l2Sam` | 所有 `hnIds` |
| 每个 shadow RN | `shadowSam` | 同一组 `hnIds` |
| 每个 HN | `hnfSam` | 所有 `dramIds` |

这意味着：

1. `Mesh0` 的主请求并不是“固定走最近的 L3”。
2. `Mesh14` 的 shadow 请求也不是“固定走某一个 L3”。
3. 两者面对的是**同一组 HN 目标表**，区别只在于请求地址是否被 shadow remap 过。

因此，想判断最终走 `Mesh6` 还是 `Mesh8`，关键不是源节点位置，而是：

```text
该请求地址在当前 SAM 哈希下得到的 XOR 结果
```

## 5. bit 编号与地址理解

为避免混淆，本文统一采用以下 bit 编号规则：

| bit 位 | 数值 |
|---|---|
| `bit0` | `2^0` |
| `bit1` | `2^1` |
| ... | ... |
| `bit31` | `2^31` |
| `bit32` | `2^32` |

因此：

```text
0x80000000 = 2^31
```

它的含义不是“很多高位都为 1”，而是：

| 地址 | 为 1 的 bit |
|---|---|
| `0x80000000` | 只有 `bit31 = 1` |

而：

```text
0x100000000 = 2^32
```

表示：

| 地址 | 为 1 的 bit |
|---|---|
| `0x100000000` | 只有 `bit32 = 1` |

## 6. shadow 地址重映射机制

当前 shadow 地址重映射公式为：

```text
A' = dst_base + (A - src_base)
```

本次运行中：

| 参数 | 值 |
|---|---:|
| `src_base` | `0x80000000` |
| `dst_base` | `0x100000000` |
| `window_size` | `0x80000000` |

所以可化简为：

```text
A' = A + 0x80000000
```

又因为本次主地址窗口是：

```text
[0x80000000, 0x100000000)
```

这个区间里的任意地址都可以写成：

```text
A = 0x80000000 + x, 其中 0 <= x < 0x80000000
```

shadow 后：

```text
A' = A + 0x80000000
   = 0x100000000 + x
```

这有一个非常重要的结论：

| 位模式变化 | 结果 |
|---|---|
| `bit31` 上原本固定存在的那个高位 `1` | 被“抬升”到 `bit32` |
| 低 `31` 位的 `x` | 完全不变 |

对本次窗口内地址而言，可以等价理解为：

| bit 位 | 原地址 | shadow 地址 |
|---|---:|---:|
| `bit31` | `1` | `0` |
| `bit32` | `0` | `1` |
| 其他 `bit6..bit51` | 不变 | 不变 |

## 7. 为什么 shadow 不改变 HN 选择结果

在 2-HN 情况下，SAM 只看：

```text
X = XOR(PA[6], PA[7], ..., PA[51])
```

而 shadow 对本次窗口内地址的影响仅为：

| 操作 | 影响 |
|---|---|
| 去掉 `bit31` 上的一个 `1` | XOR 翻转一次 |
| 增加 `bit32` 上的一个 `1` | XOR 再翻转一次 |

于是：

```text
X' = X ^ 1 ^ 1 = X
```

所以对本次运行配置，存在如下严格结论：

| 原始请求地址 A 的去向 | shadow 地址 A' 的去向 |
|---|---|
| `Mesh6` | 仍然是 `Mesh6` |
| `Mesh8` | 仍然是 `Mesh8` |

换句话说：

> 对本次运行中的同一个原始请求地址，`Mesh0` 主 L2 与 `Mesh14` shadow L2 的 HN 选择结果一定相同。

## 8. 本次运行中的实际地址例子

本次运行里，`simerr.log` 给出了主 L2 实际观测到的地址范围：

| 项目 | 值 |
|---|---:|
| `observed_addr_range.min` | `0x80000000` |
| `observed_addr_range.max` | `0xfa395fc0` |

下面用这两个运行中真实出现过的地址做示例。

### 8.1 例子 A：`0x80000000`

原始地址：

```text
0x80000000 = 2^31
```

| 项目 | 值 |
|---|---|
| 原地址为 1 的参与哈希 bit | `[31]` |
| XOR 结果 | `1` |
| 目标 HN | `HNs1 = Mesh8` |

shadow 地址：

```text
0x80000000 + 0x80000000 = 0x100000000 = 2^32
```

| 项目 | 值 |
|---|---|
| shadow 地址为 1 的参与哈希 bit | `[32]` |
| XOR 结果 | `1` |
| 目标 HN | `HNs1 = Mesh8` |

结论：

| 地址 | 去向 |
|---|---|
| `0x80000000` | `Mesh8` |
| `0x100000000` | `Mesh8` |

### 8.2 例子 B：`0xfa395fc0`

这个地址是本次运行中观测到的最大地址之一，也是一个更“非平凡”的真实例子。

原始地址：

| 项目 | 值 |
|---|---|
| 原地址 | `0xfa395fc0` |
| 参与哈希为 1 的 bit 集合 | `[6, 7, 8, 9, 10, 11, 12, 14, 16, 19, 20, 21, 25, 27, 28, 29, 30, 31]` |
| 置位个数 | `18` |
| XOR 结果 | `0` |
| 目标 HN | `HNs0 = Mesh6` |

shadow 地址：

```text
0xfa395fc0 + 0x80000000 = 0x17a395fc0
```

| 项目 | 值 |
|---|---|
| shadow 地址 | `0x17a395fc0` |
| 参与哈希为 1 的 bit 集合 | `[6, 7, 8, 9, 10, 11, 12, 14, 16, 19, 20, 21, 25, 27, 28, 29, 30, 32]` |
| 置位个数 | `18` |
| XOR 结果 | `0` |
| 目标 HN | `HNs0 = Mesh6` |

注意这里与原地址相比，唯一变化就是：

| 原地址 | shadow 地址 |
|---|---|
| 有 `bit31` | 没有 `bit31` |
| 没有 `bit32` | 有 `bit32` |

其余参与哈希的位保持不变，因此总奇偶性不变。

结论：

| 地址 | 去向 |
|---|---|
| `0xfa395fc0` | `Mesh6` |
| `0x17a395fc0` | `Mesh6` |
