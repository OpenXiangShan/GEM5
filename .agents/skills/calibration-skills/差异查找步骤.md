# XS-GEM5 与 XS-RTL 周回归差异查找步骤

以下以 SPEC CPU2006 的 `spec06-rva23-novec-gcc16-1.0c` 为例。每周重复比较时，替换运行编号，保持任务、评分单位和差异计算方式一致。

1. **选取最新的同一周的两次运行。** 打开 [XS-GEM5 周回归](https://github.com/OpenXiangShan/GEM5/actions/workflows/gem5-ideal-btb-perf-weekly.yml) 和 [XS-RTL 周回归](https://github.com/OpenXiangShan/XiangShan/actions/workflows/weekly.yml)，确认目标任务已生成评分报告。记录两端的日期、运行编号和任务链接。例如：gem5 为 2026-11-12 的 #123，RTL 为 2026-11-13 的 #22（UTC）。

2. **核对任务和配置，取两边的原始分数。** 两端的 benchmark 配置都应为 `spec06-rva23-novec-gcc16-1.0c`。
   - **gem5：** 打开 [`align_test_spec06 / XS-GEM5 - Run performance test (spec06-rva23-novec-gcc16-1.0c)`](https://github.com/OpenXiangShan/GEM5/actions/runs/43315596206/job/131522690113)，读取 Summary 中的 `score` 列；也可从 `score-spec06-rva23-novec-gcc16-1.0c` 评分包读取同源的 `score.txt`。不要误选名称相近的 `perf_test_spec06` 或 `score-ideal-*`。
   - **RTL：** 选择 [`Run SPEC06 GCC16 Performance Test`](https://github.com/OpenXiangShan/XiangShan/actions/runs/43405877024/job/131842967647)，从该次运行的 `score` 评分包读取 `score-spec06-rva23-novec-gcc16-1.0c.txt` 的 `score` 列。不要选 `score-xscc` 或 `score-spec17`。

3. **按子项名称配对，并检查覆盖率。** 用 benchmark 名称匹配，而不是按行号匹配，例如 gem5 的 `mcf` 对应 RTL 的 `429.mcf`。检查 12 个 INT、17 个 FP 子项是否一一对应；若缺项，标为“缺失”，不要补零。核对两端的 `coverage` 和失败 checkpoint：本例仅 `453.povray` 覆盖率不同（gem5 为 100%，RTL 为 96.3%），需在表中注明，即使工作流状态为成功。

4. **保留原始分数，计算两列差异。** 统一使用分/GHz，不要混入 3.0 GHz 折算分数。以 gem5 为基准：`分差 = RTL − gem5`，`相对差(%) = (RTL − gem5) / gem5 × 100`。正值表示 RTL 较高，负值表示 gem5 较高；若基准为零或任一侧缺失，相对差记为“不适用”。表格按下列格式输出；INT、FP 和总分的汇总行直接取自评分报告，不对各子项做算术平均。

   | 类别 | 子项 | XS-GEM5（分/GHz） | XS-RTL（分/GHz） | 分差（分/GHz） | 相对差 |
   |---|---|---:|---:|---:|---:|
   | INT | 429.mcf | 23.515 | 28.158 | +4.643 | +19.74% |

5. **分别找出 INT 和 FP 差异最大的三项。** 排除汇总行，把子项按 INT、FP 分组；每组按**相对差的绝对值**从大到小取前三，展示时保留正负号。若要比较“相差多少分”而非“相差百分之几”，则改按 `|RTL − gem5|` 排序，并标明口径。

   | 相对差排名 | INT | FP |
   |---:|---|---|
   | 1 | 429.mcf（+19.74%） | 465.tonto（+31.39%） |
   | 2 | 483.xalancbmk（+7.61%） | 434.zeusmp（+22.64%） |
   | 3 | 471.omnetpp（+6.94%） | 410.bwaves（+22.22%） |

6. **把本地 GEM5 和 XiangShan 仓库更新到最新，并汇报冲突情况。** 完成差异对比后，分别检查自己工作目录中的两个仓库，记录仓库路径、当前分支、上游分支、更新前提交及工作区状态。**每次更新 GEM5，都先切回 `xs-dev`，再执行 `git pull`，不要在对齐实验分支上直接拉取主线。** 工作区允许安全切换时，在 GEM5 仓库中执行 `git switch xs-dev && git pull --ff-only origin xs-dev`；其中 `origin` 应对应 OpenXiangShan/GEM5，远端名不同时替换为实际名称。已有对齐分支继续保留。

   XiangShan 通常更新 `kunminghu-v3`，用户指定分支时以指定值为准；在确认的目标分支上拉取对应远端的最新引用（`git fetch <远端名>`），再执行 `git merge --ff-only '@{upstream}'`。两端已是最新则直接记录，可以快进则完成更新。保留本地提交和未提交修改，不自动执行强制重置、清理或覆盖；未提交的实验修改应先保存在原实验分支，不能随分支切换带入主线。仓库更新后的提交用于后续定位，差异报告中的双端版本仍记录产生本次评分的实际提交。

   **有对齐实现时，先新开分支尝试。** 涉及 GEM5 或 XiangShan 的实现修改、隔离补丁或插桩时，在要修改的仓库中从本次实验确认的基线新建专用分支，例如 `git switch -c align/<feature>-<日期> <基线提交>`，再修改和验证；新的独立尝试使用新的分支名。记录分支名、基线提交和实验提交，保持主线分支用于更新。复现历史差距时仍从报告对应基线建分支，不能因主线已更新就替换历史基线。之后再次更新 GEM5，仍先切回 `xs-dev`。

   **GEM5 实现直接在原目录进行。** 使用 `/nfs/home/zhenhao/AUTO-Calibration/GEM5`，在该目录新建实验分支后修改、编译和验证，默认不另建 worktree 或克隆。交付时原目录应停留在本次实验分支。个人 AM 副本和全部日志、trace 继续保存在独立实验目录；保留已有实验分支和用户修改。已有临时工作树中的实现先保存提交，再应用到原目录的新分支，并核对与已验证代码一致。详细操作遵循[差异定位步骤的源码分支约定](./差异定位步骤.md#1-准备自己的工作目录拷贝并配置-am)。

   **两个仓库都要汇报：** 路径、分支及上游、更新前后提交、更新结果（已更新／已是最新／受阻），以及是否有冲突。用 `git status` 和 `git diff --name-only --diff-filter=U` 检查未解决的冲突；若有冲突，列出文件，暂停该仓库的后续修改，明确询问用户：“此仓库存在以下冲突，请人工处理；处理完成后是否继续更新？”等待用户回复并确认冲突已解决后再继续，不自行选择任一侧内容。

   快进失败可能是目标主线分支分叉，并不代表已经发生文件冲突；对齐实验分支与主线分叉本身不妨碍切回主线更新。若本地修改阻止安全切换或更新、目标分支缺失、上游配置异常或网络失败，应分别说明。需要人工决定如何保留未提交修改或合并主线分叉时，汇报具体状态并询问处理方式，不能将更新失败写成“已更新、无冲突”。一个仓库受阻时，仍检查另一个仓库并分别汇报结果。

本例的 29 个子项和汇总分数见[完整对比表](./spec06-compare-gem5-123-rtl-22.md)。

## 从评分追到原始数据

- **gem5 #123：** 查看 `align_test_spec06` 的 Summary → `Archive output` → `Path`。本例归档根目录为 `/nfs/home/share/gem5_ci/performance_data/spec06-rva23-novec-gcc16-1.0c/20261113_060646_f9649a04ee_kmhv3_run123`。用 `metadata.txt` 核对配置与运行编号；各切片输出在 `spec_all/` 下。
- **RTL #22：** 打开 `score-spec06-rva23-novec-gcc16-1.0c.txt` → `Other Information` → `Data Directory`。本例为 `/nfs/home/cirunner/perf-report/cr261113-8b15f0652-DefaultConfig`。该目录含多种配置，不要把目录下所有切片都算作本次 SPEC06 GCC16 的结果。
- **切片配对示例：** `429.mcf` 的切片 `10206` 在 gem5 归档内对应 `spec_all/mcf_10206/m5out/stats.txt`，在 RTL 归档内对应 `mcf_10206_0.055122/simulator_err.txt`（含 `[PERF]` 性能计数器）。RTL 同目录的 `simulator_out.txt` 记录了实际加载的 checkpoint 镜像，可用来核对输入。
